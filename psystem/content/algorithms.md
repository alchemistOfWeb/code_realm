## Сложность алгоритмов <!-- difficulty: 1 -->

Чтобы сравнивать алгоритмы, оценивают, как растут время и память при росте входных данных `n`.

### Нотация O-большое

- **O-большое** — верхняя оценка роста времени или памяти алгоритма при больших n, без констант и младших слагаемых.
- **Константная сложность** — O(1): время не зависит от размера входа, например доступ к элементу массива по индексу.
- **Линейная сложность** — O(n): один проход по данным.
- **Логарифмическая сложность** — O(log n): на каждом шаге задача уменьшается в разы, как в бинарном поиске.

Порядок роста: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!).

```python
def has_duplicate(nums):          # O(n²): два вложенных цикла
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] == nums[j]:
                return True
    return False

def has_duplicate_fast(nums):     # O(n): множество
    return len(set(nums)) != len(nums)
```

Константы отбрасываются: `O(2n + 5)` = `O(n)`. Складываются последовательные части, перемножаются вложенные.

### Время и память

Кроме времени важна **пространственная сложность** — сколько дополнительной памяти нужно алгоритму.

- **Пространственная сложность** — объём дополнительной памяти в зависимости от n (без учёта самого входа).
- **Компромисс время-память** — часто можно ускорить алгоритм, потратив память (кэш, хеш-таблица, предподсчёт).

```python
def fib(n, memo={}):      # время O(n), память O(n) на мемо и стек вызовов
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

Рекурсия тратит память на **стек вызовов**: глубина рекурсии n → O(n) памяти.

### Лучший, худший и средний случай

- **Худший случай** — максимальное время на входе размера n; обычно именно его называют на собесе.
- **Средний случай** — ожидаемое время на случайных данных (например, quicksort в среднем O(n log n)).
- **Амортизированная сложность** — средняя стоимость операции в длинной последовательности: append в динамический массив — амортизированно O(1), хотя иногда происходит расширение за O(n).

```python
items = []
for i in range(10):
    items.append(i)   # иногда list перевыделяет память, но в среднем append — O(1)
```

- Почему `list.append` — O(1), если иногда массив копируется? → амортизация: удвоение ёмкости.

## Массивы и строки <!-- difficulty: 1 -->

Самые частые задачи на собесе — про массивы и строки. Ключевые приёмы: два указателя, скользящее окно, префиксные суммы.

### Динамический массив

Python `list` — **динамический массив**: элементы лежат подряд, доступ по индексу за O(1), вставка в начало — O(n).

- **Динамический массив** — массив, который при заполнении выделяет больший блок памяти и копирует туда элементы.
- **Срез** — `a[i:j]` создаёт новую копию за O(j − i).

```python
a = [3, 1, 4]
a.append(1)        # O(1) амортизированно
a.insert(0, 9)     # O(n): сдвиг всех элементов
a[1:3]             # копия [3, 1]
```

<!-- quiz: Почему вставка в начало списка Python медленная? | +Нужно сдвинуть все элементы — O(n) | Список хранится как связный список | Python копирует весь словарь | Она быстрая — O(1) || list — непрерывный массив, вставка в начало сдвигает все элементы. -->

### Два указателя

- **Два указателя** — приём, когда два индекса движутся по массиву навстречу или в одну сторону, заменяя вложенный цикл одним проходом.

```python
def two_sum_sorted(nums, target):   # nums отсортирован, O(n)
    l, r = 0, len(nums) - 1
    while l < r:
        s = nums[l] + nums[r]
        if s == target:
            return l, r
        if s < target:
            l += 1
        else:
            r -= 1
    return None

def is_palindrome(s):
    s = [c.lower() for c in s if c.isalnum()]
    return s == s[::-1]
```

Задачи: палиндром, сумма двух в отсортированном массиве, удаление дубликатов на месте, «контейнер с водой».

### Скользящее окно

- **Скользящее окно** — подотрезок массива, который расширяют справа и сужают слева, поддерживая нужное свойство за один проход.

```python
def longest_unique_substring(s):     # O(n)
    seen = {}
    left = best = 0
    for right, ch in enumerate(s):
        if ch in seen and seen[ch] >= left:
            left = seen[ch] + 1
        seen[ch] = right
        best = max(best, right - left + 1)
    return best
```

### Префиксные суммы

- **Префиксная сумма** — массив, где p[i] — сумма первых i элементов; сумма отрезка [l, r) считается как p[r] − p[l] за O(1).

```python
from itertools import accumulate
nums = [2, 4, 1, 3]
p = [0, *accumulate(nums)]     # [0, 2, 6, 7, 10]
range_sum = p[3] - p[1]        # 4 + 1 = 5
```

## Хеш-таблицы <!-- difficulty: 1 -->

`dict` и `set` в Python — хеш-таблицы: поиск, вставка и удаление в среднем за O(1).

### Как устроена хеш-таблица

- **Хеш-функция** — функция, превращающая ключ в число, по которому выбирается ячейка таблицы.
- **Коллизия** — ситуация, когда разные ключи попадают в одну ячейку.
- **Коэффициент заполнения** — доля занятых ячеек; при его росте таблица увеличивается и элементы перераспределяются.

Коллизии решают **цепочками** (список в ячейке) или **открытой адресацией** (поиск следующей свободной ячейки — так в CPython).

Ключ должен быть **хешируемым**: неизменяемым и с постоянным `hash`. Поэтому `list` не может быть ключом, а `tuple` из чисел — может.

### Подсчёт частот и two sum

```python
from collections import Counter

def is_anagram(a, b):
    return Counter(a) == Counter(b)

def two_sum(nums, target):           # O(n) вместо O(n²)
    index = {}
    for i, x in enumerate(nums):
        if target - x in index:
            return index[target - x], i
        index[x] = i
```

- **Counter** — словарь-счётчик из `collections`: считает, сколько раз встречается каждый элемент.

## Связные списки <!-- difficulty: 2 -->

### Устройство связного списка

- **Связный список** — цепочка узлов, где каждый хранит значение и ссылку на следующий узел.
- **Двусвязный список** — узлы хранят ссылки и на следующий, и на предыдущий элемент.

Доступ по индексу — O(n), но вставка/удаление при известном узле — O(1). `collections.deque` реализован на двусвязных блоках.

```python
class Node:
    def __init__(self, val, next=None):
        self.val, self.next = val, next

head = Node(1, Node(2, Node(3)))
```

<!-- quiz: За сколько выполняется доступ к k-му элементу односвязного списка? | +O(k) — нужно пройти k узлов | O(1) | O(log k) | O(k²) || Узлы не лежат подряд, по ссылкам идём последовательно. -->

### Разворот списка

```python
def reverse(head):
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next
    return prev
```

Классика собеса: развернуть итеративно (O(1) памяти) и рекурсивно (O(n) стек вызовов).

<!-- quiz: Сколько дополнительной памяти нужно итеративному развороту связного списка? | +O(1) | O(n) | O(log n) | O(n²) || Достаточно трёх указателей: prev, текущий, следующий. -->

### Быстрый и медленный указатель

- **Алгоритм Флойда** — поиск цикла в списке: медленный указатель шагает на 1, быстрый на 2; если есть цикл, они встретятся.

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False
```

Тот же приём находит середину списка: когда быстрый дошёл до конца, медленный — в середине.

## Стек и очередь <!-- difficulty: 1 -->

### Стек

- **Стек** — структура LIFO: последним пришёл — первым вышел; операции push и pop за O(1).

В Python стек — обычный `list` (`append` / `pop`).

```python
def valid_brackets(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif not stack or stack.pop() != pairs[ch]:
            return False
    return not stack
```

### Очередь и deque

- **Очередь** — структура FIFO: первым пришёл — первым вышел.
- **Дек** — двусторонняя очередь: добавление и удаление с обоих концов за O(1).

```python
from collections import deque
q = deque([1, 2])
q.append(3)        # в конец
q.popleft()        # из начала за O(1); у list.pop(0) — O(n)
```

### Монотонный стек <!-- optional -->

- **Монотонный стек** — стек, элементы которого всегда упорядочены; позволяет найти ближайший больший/меньший элемент за O(n).

```python
def next_greater(nums):
    res = [-1] * len(nums)
    stack = []                        # индексы, значения убывают
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            res[stack.pop()] = x
        stack.append(i)
    return res
```

## Рекурсия и перебор с возвратом <!-- difficulty: 2 -->

### Рекурсия и стек вызовов

- **Рекурсия** — функция вызывает саму себя для подзадачи меньшего размера.
- **Базовый случай** — условие остановки рекурсии, без которого она бесконечна.

```python
def factorial(n):
    if n <= 1:          # базовый случай
        return 1
    return n * factorial(n - 1)
```

У Python ограничена глубина рекурсии (~1000) — `RecursionError`. Глубокую рекурсию переписывают на цикл со своим стеком.

<!-- quiz: Что произойдёт при рекурсии без базового случая в Python? | +RecursionError: превышена глубина рекурсии | Бесконечный цикл без ошибок | Python сам добавит базовый случай | SyntaxError || Каждый вызов занимает кадр стека, лимит ~1000. -->

### Мемоизация

- **Мемоизация** — кэширование результатов функции для уже встречавшихся аргументов.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)   # O(n) вместо O(2ⁿ)
```

<!-- quiz: Как мемоизация меняет сложность наивного рекурсивного Фибоначчи? | +С O(2ⁿ) до O(n) | С O(n) до O(1) | Не меняет | С O(n²) до O(n log n) || Каждое значение считается один раз. -->

### Перебор с возвратом

- **Backtracking** — построение решения по шагам с откатом последнего выбора, если он ведёт в тупик.

```python
def permutations(nums):
    res, path, used = [], [], [False] * len(nums)
    def go():
        if len(path) == len(nums):
            res.append(path[:])
            return
        for i, x in enumerate(nums):
            if not used[i]:
                used[i] = True; path.append(x)
                go()
                path.pop(); used[i] = False    # откат
    go()
    return res
```

Задачи: перестановки, подмножества, N ферзей, судоку, комбинации с суммой.

## Сортировки <!-- difficulty: 2 -->

### Квадратичные сортировки

- **Сортировка пузырьком** — многократно меняет местами соседние элементы, стоящие не по порядку; O(n²).
- **Сортировка вставками** — вставляет каждый элемент на своё место в уже отсортированной части; O(n²), но быстра на почти отсортированных данных.

```python
def insertion_sort(a):
    for i in range(1, len(a)):
        x, j = a[i], i - 1
        while j >= 0 and a[j] > x:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = x
```

<!-- quiz: На каких данных сортировка вставками работает почти за O(n)? | +На почти отсортированных | На случайных | На отсортированных в обратном порядке | Ни на каких || Каждый элемент сдвигается лишь на несколько позиций. -->

### Сортировка слиянием

- **Сортировка слиянием** — делит массив пополам, сортирует половины рекурсивно и сливает; всегда O(n log n), память O(n).

```python
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    res, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            res.append(left[i]); i += 1
        else:
            res.append(right[j]); j += 1
    return res + left[i:] + right[j:]
```

<!-- quiz: Какая сложность сортировки слиянием в худшем случае? | +O(n log n) | O(n²) | O(n) | O(log n) || Глубина log n уровней, на каждом слияние за O(n). -->

### Быстрая сортировка

- **Быстрая сортировка** — выбирает опорный элемент, раскладывает меньшие влево, большие вправо и сортирует части; в среднем O(n log n), в худшем O(n²).

Плохой опорный элемент (например, всегда первый на отсортированном массиве) даёт O(n²). Случайный опорный элемент делает худший случай маловероятным.

### Устойчивость и Timsort

## Бинарный поиск <!-- difficulty: 2 -->

### Классический бинарный поиск

- **Бинарный поиск** — поиск в отсортированном массиве делением отрезка пополам; O(log n).

```python
def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

Главное условие — массив **отсортирован**.

<!-- quiz: Сколько шагов нужно бинарному поиску в массиве из миллиона элементов? | +Около 20 | Около 1000 | Около 500 000 | Около 100 || log₂(10⁶) ≈ 20. -->

### Поиск границ

Часто нужна не любая позиция, а **первая** или **последняя** подходящая. В Python для этого есть `bisect`.

```python
import bisect
a = [1, 2, 2, 2, 5]
bisect.bisect_left(a, 2)    # 1 — первая позиция двойки
bisect.bisect_right(a, 2)   # 4 — позиция после последней двойки
```

### Бинарный поиск по ответу <!-- optional -->

- **Бинарный поиск по ответу** — подбор минимального подходящего значения, если проверка «подходит ли x» монотонна.

```python
def min_speed(piles, hours):          # «Коко ест бананы»
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if sum((p + mid - 1) // mid for p in piles) <= hours:
            hi = mid
        else:
            lo = mid + 1
    return lo
```

## Деревья <!-- difficulty: 2 -->

### Двоичные деревья и обходы

- **Двоичное дерево** — дерево, у каждого узла которого не больше двух детей.
- **Обход в глубину** — посещение узлов с уходом вглубь ветки: прямой (pre-order), центрированный (in-order) и обратный (post-order).
- **Обход в ширину** — посещение узлов по уровням с помощью очереди.

```python
def inorder(node):
    if node:
        yield from inorder(node.left)
        yield node.val
        yield from inorder(node.right)

def max_depth(node):
    return 0 if node is None else 1 + max(max_depth(node.left), max_depth(node.right))
```

### Двоичное дерево поиска

- **Двоичное дерево поиска** — дерево, где в левом поддереве все ключи меньше узла, а в правом — больше.

Поиск, вставка и удаление — O(h), где h — высота. В сбалансированном дереве h = O(log n), в вырожденном (цепочка) — O(n).

Центрированный обход дерева поиска выдаёт ключи **по возрастанию**.

<!-- quiz: Какая высота у дерева поиска, если вставлять ключи 1, 2, 3, …, n по порядку? | +n — дерево вырождается в цепочку | log n | 1 | √n || Каждый новый ключ становится правым ребёнком предыдущего. -->

### Сбалансированные деревья <!-- optional -->

- **AVL-дерево** — дерево поиска, где высоты поддеревьев любого узла отличаются не больше чем на 1; балансируется поворотами.
- **Красно-чёрное дерево** — дерево поиска с раскраской узлов, гарантирующей высоту O(log n); используется в TreeMap Java и std::map C++.

В Python нет встроенного сбалансированного дерева: обходятся `sorted` + `bisect`, кучей или библиотекой `sortedcontainers`.

<!-- quiz: Зачем нужны повороты в AVL-дереве? | +Чтобы восстановить баланс высот и сохранить O(log n) | Чтобы отсортировать ключи | Чтобы удалить дубликаты | Чтобы превратить дерево в кучу || Поворот меняет форму дерева, не нарушая порядок ключей. -->

### Префиксное дерево

- **Trie** — дерево, где каждый путь от корня — префикс строки; поиск слова или префикса за O(длины слова).

```python
class Trie:
    def __init__(self):
        self.root = {}
    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
        node["$"] = True
    def starts_with(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node:
                return False
            node = node[ch]
        return True
```

Применение: автодополнение, словари, поиск слов на поле.

## Кучи и приоритетные очереди <!-- difficulty: 2 -->

### Двоичная куча

- **Двоичная куча** — почти полное двоичное дерево, где каждый родитель не больше своих детей (min-куча); хранится в массиве.
- **Приоритетная очередь** — структура, которая быстро отдаёт элемент с наименьшим (или наибольшим) приоритетом.

Вставка и извлечение минимума — O(log n), просмотр минимума — O(1), построение кучи из массива — O(n).

```python
import heapq
h = [5, 1, 4]
heapq.heapify(h)          # O(n)
heapq.heappush(h, 2)      # O(log n)
heapq.heappop(h)          # 1
```

В `heapq` только min-куча; для max-кучи кладут отрицательные значения.

## Графы <!-- difficulty: 3 -->

### Представление графа

- **Граф** — множество вершин и рёбер между ними; рёбра бывают направленными и взвешенными.
- **Список смежности** — для каждой вершины хранится список соседей; память O(V + E), удобен для разреженных графов.
- **Матрица смежности** — таблица V×V; проверка ребра за O(1), но память O(V²).

```python
from collections import defaultdict
graph = defaultdict(list)
for a, b in [(1, 2), (2, 3), (1, 3)]:
    graph[a].append(b)
    graph[b].append(a)     # неориентированный граф
```

<!-- quiz: Какое представление графа экономнее для разреженного графа? | +Список смежности | Матрица смежности | Они одинаковы | Куча || Список смежности занимает O(V + E), матрица — O(V²). -->

### Обход в ширину и в глубину

```python
from collections import deque

def bfs(graph, start):          # кратчайший путь в рёбрах в невзвешенном графе
    dist = {start: 0}
    q = deque([start])
    while q:
        v = q.popleft()
        for u in graph[v]:
            if u not in dist:
                dist[u] = dist[v] + 1
                q.append(u)
    return dist

def dfs(graph, v, seen):
    seen.add(v)
    for u in graph[v]:
        if u not in seen:
            dfs(graph, u, seen)
```

Обе работают за O(V + E). BFS даёт кратчайшие пути в невзвешенном графе, DFS — компоненты связности, поиск циклов.

<!-- quiz: Каким обходом искать кратчайший путь в невзвешенном графе? | +В ширину (BFS) | В глубину (DFS) | Алгоритмом Флойда для списков | Сортировкой || BFS посещает вершины в порядке удаления от старта. -->

### Топологическая сортировка

- **Топологическая сортировка** — упорядочивание вершин ориентированного графа без циклов так, чтобы каждое ребро шло слева направо.

```python
from collections import deque

def topo_sort(n, edges):        # алгоритм Кана
    indeg = [0] * n
    graph = [[] for _ in range(n)]
    for a, b in edges:
        graph[a].append(b); indeg[b] += 1
    q = deque(i for i in range(n) if indeg[i] == 0)
    order = []
    while q:
        v = q.popleft(); order.append(v)
        for u in graph[v]:
            indeg[u] -= 1
            if indeg[u] == 0:
                q.append(u)
    return order if len(order) == n else None   # None — есть цикл
```

Применение: порядок сборки зависимостей, расписание курсов.

<!-- quiz: Когда топологическая сортировка невозможна? | +Если в графе есть цикл | Если граф неориентированный и связный | Если вершин больше 100 | Всегда возможна || Вершины цикла не могут стоять друг перед другом одновременно. -->

### Алгоритм Дейкстры

- **Алгоритм Дейкстры** — поиск кратчайших путей от одной вершины во взвешенном графе с неотрицательными весами; O((V + E) log V) с кучей.

```python
import heapq

def dijkstra(graph, start):          # graph[v] = [(u, w), ...]
    dist = {start: 0}
    heap = [(0, start)]
    while heap:
        d, v = heapq.heappop(heap)
        if d > dist.get(v, float("inf")):
            continue
        for u, w in graph[v]:
            nd = d + w
            if nd < dist.get(u, float("inf")):
                dist[u] = nd
                heapq.heappush(heap, (nd, u))
    return dist
```

При отрицательных весах нужен **алгоритм Беллмана — Форда** (O(V·E)).

### Система непересекающихся множеств <!-- optional -->

- **Union-Find** — структура, которая хранит разбиение на группы и умеет объединять группы и проверять, в одной ли группе элементы; почти O(1) на операцию.

```python
parent = list(range(n))
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]   # сжатие путей
        x = parent[x]
    return x
def union(a, b):
    parent[find(a)] = find(b)
```

Применение: компоненты связности, алгоритм Краскала для минимального остовного дерева.

## Динамическое программирование <!-- difficulty: 3 -->

### Идея динамического программирования

- **Динамическое программирование** — решение задачи через ответы на перекрывающиеся подзадачи, каждая из которых считается один раз.
- **Оптимальная подструктура** — свойство, при котором оптимальный ответ строится из оптимальных ответов подзадач.

Шаги: определить **состояние** (что значит dp[i]), **переход** (как dp[i] выражается через меньшие), базу и порядок вычисления.

Подходы: сверху вниз (рекурсия + мемоизация) и снизу вверх (заполнение таблицы).

<!-- quiz: Чем динамическое программирование отличается от простой рекурсии? | +Ответы перекрывающихся подзадач сохраняются и не пересчитываются | ДП всегда работает за O(1) | ДП не использует подзадачи | Ничем || Без сохранения одни и те же подзадачи считаются экспоненциально много раз. -->

### Одномерная ДП

```python
def climb_stairs(n):          # шаги по 1 или 2 ступени
    a, b = 1, 1
    for _ in range(n):
        a, b = b, a + b
    return a

def rob(houses):              # «грабитель»: нельзя брать соседние дома
    take = skip = 0
    for x in houses:
        take, skip = skip + x, max(take, skip)
    return max(take, skip)
```

Часто таблицу можно сжать до нескольких переменных — память O(1).

<!-- quiz: Сколько памяти нужно задаче о лестнице, если хранить только два предыдущих значения? | +O(1) | O(n) | O(n²) | O(log n) || dp[i] зависит только от dp[i−1] и dp[i−2]. -->

### Двумерная ДП

```python
def lcs(a, b):                # наибольшая общая подпоследовательность, O(n·m)
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]
```

- **Задача о рюкзаке** — выбор предметов с весами и ценностями в рюкзак ограниченной вместимости; dp по предметам и весу за O(n·W).
- **Расстояние Левенштейна** — минимальное число вставок, удалений и замен символов, превращающих одну строку в другую.

<!-- quiz: Какая сложность у LCS двух строк длины n и m? | +O(n·m) | O(n + m) | O(2ⁿ) | O(n log m) || Таблица (n+1)×(m+1), каждая ячейка за O(1). -->

### Жадные алгоритмы <!-- optional -->

- **Жадный алгоритм** — на каждом шаге делает локально лучший выбор; работает, только если локальный оптимум ведёт к глобальному.

```python
def max_meetings(intervals):          # выбор непересекающихся встреч
    count, end = 0, float("-inf")
    for s, e in sorted(intervals, key=lambda x: x[1]):
        if s >= end:
            count += 1
            end = e
    return count
```

Контрпример: размен монетами 1, 3, 4 суммы 6 — жадно 4+1+1 (3 монеты), а оптимально 3+3 (2 монеты). Тогда нужна ДП.
